# Call recordings

Real, decoded-audio proof of one full call lifecycle through the live stack (SBC → Kamailio → FreeSWITCH), generated by `test/sipp/call-recording-check.sh` or `test/sipp/call-recording-check-connected.sh`. Re-run either to generate a fresh timestamped directory; nothing here is hand-edited.

## What's in each run's directory

| File | What it is |
|---|---|
| `call.pcap` | Full capture from the SBC's own interface, start to hangup |
| `audio.wav` | Decoded FreeSWITCH → SBC RTP payload (PCMU → WAV) |
| `packets-per-second.txt` | RTP packet counts per second, FreeSWITCH → SBC |
| `volume.txt` | `ffmpeg -af volumedetect` output for `audio.wav` |
| `address-hygiene.txt` | `check-addresses.sh` result (pod-IP leak check) |
| `summary.txt` | Pass/fail verdict |

## [20261104-204453](20261104-204453/): final validated run

Scenario: `local/sbc/scenarios/uac-demo-hold.xml` against FreeSWITCH's `demo_voice` extension (9199): answer, listen to the real greeting, hold (re-INVITE `a=sendonly`), wait, unhold (re-INVITE `a=sendrecv`), listen to more real audio, hang up.

Run after fixing three real bugs a load test (see ADR 002) surfaced while testing this same path: a stale static dispatcher seed, a `dispatcher-sync` bug that made it give up for a whole poll tick whenever the live list was legitimately empty, and FreeSWITCH having no `readinessProbe` (so a brand-new replica could take a call before Sofia was listening). All three are fixed; this recording is the clean, current state, not the first attempt.

- **Call completed end-to-end**: all 17 SIP messages (INVITE/hold/unhold/BYE) got the expected response, 0 failures.
- **Hold actually silenced the stream**, not just a 200'd re-INVITE: `packets-per-second.txt` shows FreeSWITCH → SBC RTP at seconds 10-12 (pre-hold), a gap at second 13 (on hold), then resuming at 14-16 (post-unhold).
- **Real audio, not silence**: `audio.wav` decodes to a mean volume of -31.9 dB, max -17.0 dB, consistent with the -31 dB reference figure in `dev-docs/verification.md`. The "more audio" segment is FreeSWITCH's hold-music file (`base256/music.wav`), which is genuine but short (~0.5s per loop), not a long musical piece.
- **SIP headers stayed clean**: `check-addresses.sh` passed against the full decoded capture (headers included); live proof that [ADR 003](../../../dev-docs/adr/003-topos-state-store.md)'s `topos`/`topos_htable` closed the pod-IP leak [ADR 001](../../../dev-docs/adr/001-necessity-review.md) found, without breaking the call.
- The dispatched FreeSWITCH replica varies run to run (dispatcher round-robin); this run landed on `192.168.50.130`; the script resolves whichever one actually took the call from the capture itself, not an assumption.

## [20261105-214407](20261105-214407/): welcome → hold → connected (real two-way audio) → hangup

Scenario: `local/sbc/scenarios/uac-call-flow.xml` against FreeSWITCH's `demo_connected` extension (9200): answer, listen to the real greeting, hold (re-INVITE `a=sendonly`), wait, unhold (re-INVITE `a=sendrecv`), send real audio into `echo()`, hang up. Unlike the `demo_voice`/9199 recording above (which plays a fixed script regardless of hold state), this proves the "connected" phase is an actual two-way call: the audio FreeSWITCH sends back is the SBC's own audio coming straight through `echo()`, not a pre-recorded prompt.

This scenario's audio (`pcap/g711a.pcap`) is PCMA (A-law, RTP payload type 8), not PCMU. The first version of this scenario negotiated PCMU, and FreeSWITCH correctly discarded every packet. That looked identical to a FreeSWITCH/hold bug until a capture showed the payload type mismatch directly. Fixed by changing the scenario's SDP to `RTP/AVP 8`/`a=rtpmap:8 PCMA/8000`.

- **Call completed end-to-end**: all 17 SIP messages (INVITE/hold/unhold/BYE) got the expected response, 0 failures.
- **Hold actually silenced the stream**: `packets-per-second.txt` shows FreeSWITCH → SBC RTP at seconds 10-13 (welcome), then nothing at 14-16 (on hold).
- **The call actually reconnected, not just a 200'd re-INVITE**: RTP resumes at second 17 (right after the unhold `200 OK`) and continues through second 21. FreeSWITCH is echoing the SBC's own audio back in real time.
- **Real audio, not silence**: `audio.wav` decodes to a mean volume of -26.5 dB, max -6.2 dB.
- **SIP headers stayed clean**: `check-addresses.sh` passed, same topos proof as the recording above.
- Run twice more (not committed) with consistent results (-26.5 dB both times, same gap/resume pattern) before trusting this one.
